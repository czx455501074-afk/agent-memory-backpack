方法：逐条读取设计文档（`docs/plans/2026-10-09-shared-agent-knowledge-plan.md`、`docs/implementation/p2-requirements.md`），在 `src/`、`adapters/`、`console/` 中检索实现痕迹，并复核每一处命中是真实现还是词面误命中。

## 结论

**设计与实现差距很大。** 设计文档描述的 6 个阶段（P0–P5）中，P1 知识底座基本落地，P2 只落地了约三分之一（审阅与任务台账），P3 的智能检索、P4 的资料生命周期与管理页、以及常驻运行机制**基本没有实现**。

需要区分的三种状态：

- **已实现**：有代码路径，且测试或真实运行可验证。
- **部分实现**：有数据结构或接口，但缺设计要求的核心行为。
- **未实现**：代码中检索不到，或只有类型定义/注释。

## 三、接口层与数据源缺口

**日记/偏好类数据没有采集源。** `discovery.ts` 的 `AdoptKind` 声明了 `preference`，`memory` 也有分支，但扫描判定只产出 `norm` / `skill` / `memory` 三种；**日记（journal）既无类型也无识别规则**，`~/.dsh/sessions`（844 文件）、`~/.dsh/memories`（35 文件）不在扫描范围内。

**检索相关性缺陷（本轮发现）。** `store.ts` 的 `knowledge()` 在无查询时返回**顺序不确定的前 5 条**；有关键词时用 `OR` 连接所有 bigram 片段，**任一片段命中即返回**。实测：查询「已重启」返回了 5 个与软件工程无关的媒体技能。这解释了注入上下文为何频繁出现无关技能。

## 四、与设计文档的一致性风险

- 设计明确「管理界面用本地 Web 页面，不重复制造桌面壳」，实现却依赖 Electron 二进制（安装成本与体积都更高）。
- 设计要求「不依赖某个聊天 shell 一直存活」的常驻核心，实现需要插件加载时才拉起，宿主关闭即无核心。

## 五、建议的优先级

1. **安装后主动同步**（用户已明确提出，且是设计承诺）——`amb-install.mjs` 接入 discover/adopt。
2. **检索相关性**——无查询时的确定性、关键词的 AND/加权，避免注入无关内容。
3. **任务日记自动生成 + 导出**——数据已在，缺生成与导出。
4. **三态运行模式与常驻/单实例**——设计承诺的运行基础。
5. **日记类数据源识别**——需要先定义采集边界（会话内容属于隐私，不能默认全采）。
6. P3/P4 的语义检索与资料生命周期——依赖前几项，且语义检索需先有评测基线。

## 六、审计后已修复项

审计完成后按优先级实现了前两项，均含测试与真实环境验证。

### 6.1 核心自启动（`86ce108` 之前）

插件加载时自行拉起核心，不再要求用户手动 `serve`。新增 `adapters/*/ensure-core.mjs`（两端逐字相同，测试断言哈希一致）：先探测、detached 启动、**从不抛错**；DSH 在加载时后台启动且绑定生命周期，Codex 在 `SessionStart` 启动。DSH 包补上了核心运行时（此前不带，无从启动）。

实测：核心 DOWN → `{"started":true}` → health 200。

### 6.2 安装后主动同步（`86ce108`）

`amb-install.mjs` 新增第 4 步：默认执行 `discover`（只读）→ `adopt`（写入，打印撤销命令）。扫描失败则跳过采纳；采纳失败报为可重试步骤而非安装失败。`--no-sync` 跳过，`--sync-roots` 收窄范围。

### 6.3 发现侧的两个真实缺陷（`48cd5e5`）

实现 6.2 时发现同步"找不到东西"，根因不在安装脚本：

**（a）符号链接形式的扫描根被跳过。** `~/.dsh/skills` 与 `~/.dsh/memories` 是指向共享数据目录的 junction。遍历拒绝一切符号链接——对**树内部**的链接这是对的（可逃出扫描范围），但根是用户自己的指针，正是它们让那些目录可达。默认扫描只报 **62** 个候选，而用户的技能就在一层链接之后，输出里没有任何一行说明它跳过了哪个目录。现在根会被解析，根以下的链接仍拒绝；已解析的根按真实路径去重，避免两个根指向同一目录时把每份文档报成自身重复。

**（b）日记不被识别。** 两端都写 `daily/<日期>.md`，而没有规则匹配它，于是落到"技能入口之外的 Markdown"被丢弃——用户要同步的日记恰恰是唯一没同步进来的东西。现在按**文件名**（而非所在文件夹）判定为 memory 类型，理由里注明是日记。同目录下非日期命名的 Markdown 仍是普通文档，规则读不成"daily 下一切都是知识"。

记忆与日记目录已加入默认扫描根。

**真实环境实测**：修复前默认扫描 62 候选；修复后 **165**（146 技能 + 16 记忆/日记 + 3 规范），无重复路径、无重复 id。实际同步把库从 **87 条补到 165 条**（`adopt --revoke 1791689875860` 可撤销）。

### 6.4 仍待处理

- 检索相关性：无查询时返回顺序不确定的前 5 条；关键词用 `OR` 松匹配（实测查询「已重启」返回 5 个媒体技能）。**尚未修复。**
- `current()` 已改为按 id 排序（`3032a92`），解决了不确定性，但未解决相关性。
- 常驻/单实例/登录自启动、任务日记自动生成与导出、三态运行模式、P3/P4 各项：均未实现。
