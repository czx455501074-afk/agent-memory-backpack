# 安装期既有知识采纳需求（P2.5）

**状态**：扫描、采纳写入与一键撤销**已实现并通过测试**；周期性重扫描未实现
**来源**：用户 2026-10-10 指令
**优先级**：高（影响安装体验与数据安全）
**实现**：`src/discovery.ts`（扫描与归类）、`src/store.ts`（采纳账本与撤销）、`src/cli.ts`（`discover` / `adopt` 命令）
**测试**：`test/discovery.test.ts`（8 项）、`test/adoption.test.ts`（6 项）

## 一、目标

插件安装后应主动发现用户 agent 中**已经存在**的规范、skill、记忆与偏好，并安全地纳入插件管理；同时必须满足两条硬约束：

1. **不影响插件运行的内容不得搬入**——采纳的必须是知识本身，不是宿主运行所需的配置、凭据、可执行逻辑。
2. **不得破坏既有工作**——包括已产生的工作成果与会话中正在进行的工作。

这不是"导入历史"，而是**接管既有知识的治理权**，因此必须默认可逆、可审计、逐项可控。

## 二、需要处理的知识来源（按宿主分列）

| 宿主 | 既有位置（相对用户主目录） | 内容形态 |
|---|---|---|
| DSH | `~/.dsh/AGENTS.md` | 项目/全局工作契约与偏好，纯 Markdown |
| DSH | `~/.dsh/profiles/<profile>/` 及插件配置 | 插件启用状态、配置（**不采纳**，见第三节） |
| DSH | `.agents/skills/<name>/SKILL.md` 及 references/ | 技能入口 + 叶子规则 |
| Codex | `~/.codex/AGENTS.md` 或仓库内 `AGENTS.md` | 工作约定 |
| Codex | `~/.codex/plugins/cache/.../skills/` | 打包资源内的技能 |
| Codex | `~/.codex/config.toml` | 插件启用与凭据（**不采纳**） |
| 两端 | 仓库内 `AGENTS.md`、`.cursor/rules`、`.github/copilot-instructions.md` 等 | 项目级约定 |

具体路径必须在实现时通过**实际探测**确认，不得凭本文表格假定；表格用于界定范围，不作为已核实事实。

## 三、采纳边界（哪些绝不搬入）

以下内容即使以知识形式出现，也**不得**写入插件库：

- 任何凭据、令牌、密钥、cookie、会话标识。
- 宿主运行配置：插件启用状态、模型路由、沙箱/权限策略、profile 选择。
- 可执行逻辑与自动化：hook 定义、脚本、CI 配置、IDE 扩展配置。
- 影响宿主启动或插件加载的清单文件（如 `dsh.client`、`plugin.json`、`cordis.patch.yml`）。
- 会话正文与对话记录（属于宿主会话存储，不复制）。
- 用户主目录中与项目无关的个人文件。

判定规则：**若移除该内容会导致宿主或插件行为变化，则不采纳**；知识条目即使被删除也只是"少一条经验"。

## 四、安全采纳流程

安装时执行一次**只读扫描 + 差异呈现 + 用户确认 + 可逆写入**：

1. **只读扫描**：仅读取文件内容，不写入、不改名、不改权限、不创建宿主侧文件。遵守宿主的忽略规则（如 `.gitignore`）与符号链接边界（不跨越到项目外，已有 `isWithinProject` 可复用）。
2. **分类**：按第三节边界把扫描结果分为 `adoptable`（规范/偏好/记忆/技能）与 `excluded`（凭据、配置、可执行逻辑），并记录排除原因。
3. **差异呈现**：与插件库现有条目比对，标记为 `new` / `duplicate` / `conflict`。冲突不自动解决。
4. **用户确认**：默认**不自动写入**。按条目或按类别批量确认；低风险且可核验的重复项可按已批准白名单自动去重（沿用规划 §6.3 的保守策略）。
5. **可逆写入**：写入遵循既有版本机制——每个采纳条目作为新版本落库，保留来源路径、采集时间与原始内容哈希。
6. **回执与撤销**：安装完成后报告采纳/跳过/冲突数量与理由；提供**一键撤销本次采纳**，撤销只删除插件库中的条目，绝不触碰源文件。

## 五、不破坏既有工作的硬约束

- **源文件只读**：整个流程对宿主文件系统只做读操作；不做移动、重命名、删除、就地修改。
- **不接管宿主加载路径**：不修改 `AGENTS.md`、`SKILL.md`、`config.toml`、profile 或任何宿主会加载的文件；插件自身的内容供给通过独立通道（MCP / 适配器注入）完成。
- **不动进行中的会话**：扫描发生在安装时；不注入到正在运行的会话上下文中，不改动会话历史。运行中的会话只在**下一次** `prepare` 时获得新增知识。
- **不阻塞**：扫描与写入不得阻塞宿主启动或用户的当前操作；耗时超过阈值时以后台任务继续并报告进度。
- **重复安装幂等**：同一来源重复采纳视为重复，不产生新版本；内容变化才生成新版本。
- **失败安全**：任一步骤失败时整体回滚插件库写入，宿主侧无残留改动。

## 七、与既有规划的衔接

本需求补强联合规划 §2（用户如何使用）与 §6（工作后的提交、审核和写入）之间的缺口：规划覆盖了"工作后如何沉淀新经验"，但未覆盖"安装时如何接管已有知识"。实现时沿用既有的候选/有效/历史分离、幂等提交与事务边界机制，不新增并行存储格式。采纳账本（`adoptions` 表）记录来源路径、内容哈希与批次时间，使撤销可精确到批次。
