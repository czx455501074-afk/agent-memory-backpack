# 同行经验对照（R5）

用户明确要求过："相关的功能实现我希望你能主动的搜索 github 上相似项目，总结它们的有用经验作用到我们的插件。"本文件把这份对照固定下来：**学到了什么、用了哪条、没用哪条、为什么。**

来源说明：下表左列的数字与结论来自本会话早期的同行调研线报告（调研对象为同类"agent 记忆/检索/审核"方向的开源项目）。**本文件不重复引用其外部链接**，因为在写这一版时没有逐条回访原仓库；因此每一条都标注了"我们是否实测"——**没有实测的只当参考，不当作结论**。采用与否的最终依据是本项目自己库的普查数字（见 `r5-usage-report.md`、`r5-next-phase-plan.md`）。

## 一、被采用的

| 同行做法 | 我们怎么做 | 我们的实测依据 |
|---|---|---|
| **每个文档只贡献一个片段**（`MCP_RAG_MAX_CHUNKS_PER_DOC=1`；报告称 R@5 从 0.5104 → 0.8676） | 召回段落在超预算时**逐条降级**（full → summary → index），而不是把同一篇的多个片段都塞进去 | W12 实测：两技能场景 11379 → **1275** 字符（−78.5%），6540 技能 2596 → **1025**，50495 的 memory 2926 → **936**；未超预算的查询逐字节不变（312 = 312） |
| **提炼要设观测门槛**（`min_observations`、最小时间跨度、置信度下限、每次产出上限、负向过滤） | `src/refine.ts` 的参数**全部改由本库普查定**：`minOccurrences=2`、`minSpanMs=120s`、`minConfidence=0.75`、`maxProposalsPerRun=5`、负向过滤当前 9 条 | 本库普查：140 条失败事实 / 47 个签名；≥2 次阈值丢掉 37 组/37 条（26%）；**把门槛提高到 8 只多去掉 5 组且不改善行覆盖**——所以没有照搬 8 |
| **审核结果要有否决与冷却结构**（拒绝缓冲、避免同一内容反复提交） | 候选有 `expires_at`、拒绝/归档状态与重开路径 | 本库：过期机制此前被"误判的 important"架空（97 → 62），已单独修复 |
| **反馈回到排序**（同行的信任分/反馈乘数，限制在窄区间） | 目前**未实现**信任分；排序只用覆盖率、主题命中、长度归一与强证据加权 | 未实测——**不写进能力清单**，列为下一阶段候选 |

## 二、看过但**没有**采用的（以及原因）

| 同行做法 | 为什么不用 |
|---|---|
| 把观测门槛直接设成 **8 次** | 本库普查显示：从 2 提到 8 只多丢掉 5 组签名，行的覆盖几乎没变（83 vs 98 / 134）——**阈值更高没有换来选择性，只丢掉真实的复现**。数字是别人的库的，不是我们的。 |
| 用**模型摘要**替代原文做交接（Jev 的 digest 路线） | 该路线自己的实测结论就是反例：摘要版交接的召回率（37.5%）显著低于直接给完整对话（更高），且"一次搜索旧会话"能再补 16–33 分。我们的做法因此是**保留原文 + 可检索**，而不是预先压成摘要。 |
| 每轮把**所有**召回片段整段注入 | 与用户最初的诉求直接冲突（"不要把大量上下文喂给 agent"）。我们改成预算 + 逐条降级 + 省略说明。 |
| 自动采纳提炼结果 / 自动升格为规范 | 与审核门禁这条产品承诺冲突。提炼器只产出建议，绝不写入。 |
| 在空流程库上要求"经验必须归属某个流程步骤" | 本库 workflow 与 task 条目均为 **0**，这条要求会让每条正常经验都变成"未归属"的例外——这正是本轮的 W11 要解开的死结。 |
| 注入检测的**细粒度语义**（区分"已判定"与"未判定"、`fail_open` 不算干净结果） | 有价值，但我们的库是**本地且由用户自己的工具写入**，威胁模型不同。列为未来候选，不做当前版本的承诺。 |

## 三、从同行学到的**方法**（比参数更值钱）

1. **同一个结论在不同数据集上会反过来**。同行的 `MAX_CHUNKS_PER_DOC=1` 与"门槛设 8"来自不同语料；前者在我们这里复现了效果，后者没有。所以本文件左列只当**假设来源**，右列的结论一律由本库数据给出。
2. **摘要化有隐藏代价**：把内容压短会让"原本能找回的那一行"消失，而损失只在长会话里显现。这直接支持我们选择"指针化 + 可检索"而不是"压缩正文"。
3. **写清"哪些数字没有被验证"**。我们的 `maxProposalsPerRun=5` 与 `minConfidence=0.75` 就是这种状态：前者是保守占位、需要审阅人反馈，后者没有按结果校准。同行把这类数字当默认值发布，我们选择把它们标成未验证。

## 四、这份对照还没有做的事

- 没有逐条回访原仓库核对参数（写这份文件时没做），所以左列数字**不应被当作最新事实**引用。
- 没有对"信任分/反馈乘数"做本库实测——它出现在上面第二张表里，但没有进入这一版能力清单。
- 没有做跨实现的质量对比（例如用同一组查询在我们的库与同行实现上分别测命中率）。这是 P5（分布级排序调参）之前值得补的一步。
