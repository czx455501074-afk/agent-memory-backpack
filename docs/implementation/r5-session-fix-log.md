# R5 修复记录：本会话解决的问题、判据与证据

本文件回答一个问题：**这一串修复各自解决什么、凭什么说它有效、怎么复现。** 每项都给出判据、前后数字与可重跑的命令。凡是没解决的，写在最后一节，不混进"已完成"。

---

## 一、注入噪声：无关查询也会被注入内容

**现象**：对真实库问"红烧肉怎么做才好吃，要放多少冰糖"，系统选中并注入了两条技能（一个短剧故事设定、一个 API 通道）。

**根因**：模型超时或弃权时，选择降级为本地索引排名（`src/retrieval-service.ts` 的 `localIds`）。消费端 `store.prepare` 已经算出严格匹配（`automaticRelevance`），却**没把它当门槛**——索引的宽松证据链（子句术语、用途命中、事实窗口）与严格匹配器（标题/描述/正文 token）判断不一致，不一致就以"注入内容"的形式送到 agent 面前。

**改动**：`src/store.ts` 消费 `selectedIds` 时，对**非 model 来源**要求 `matched` 或 `coverage` 非空。**模型选择刻意豁免**——语义相关性正是模型能看见而字面匹配看不见的东西。

**判据与数字**（`node verification/r5/selection-noise-rate.mjs`）：

| 测量 | 无关查询 | 相关查询（对照） |
|---|---|---|
| 改动前（8 + 4） | 注入 4/8，**其中零证据 4/8** | 2/4，零证据 0/4 |
| 改动后（8 + 4） | 注入 0/8，零证据 0/8 | 2/4，零证据 0/4 |
| 改动后（32 + 12） | 注入 3/32，**零证据 0/32** | 9/12，零证据 2/12 |

**对照组不变是关键证据**：若只是"拒绝更多"，两组都会掉；相关组保持原值说明没有误杀。相关组残留的 2/12 零证据注入**全部来自 `mode=model`**，即被刻意豁免的那条路径，属设计既定代价。

**为什么两次修复**：此前还提交过一次 `best <= 0` 的绝对下限（`src/retrieval-service.ts`）。它守的是一个真实边界，但**不改变本现象**——真实情况下 `best` 不为 0。已在提交信息中明示"它不改变症状"，未写成修复。

提交：`68003cc`（下限）、`566f764`（证据门槛）。

## 二、超时预算切进了模型自己的延迟分布

**现象**：相关查询中约三分之一拿不到模型判断（`local_index:model_timeout`）。

**根因**：预算写死 `2500ms`。实测 12 次相关查询，**模型作答耗时中位 2101ms、最慢 2787ms**，而**每一次超时的请求耗时都是 2871–2875ms**——不是慢得离谱，是差几十毫秒。预算落在分布**内部**而非外侧。

**改动**：改为 `3500ms` 并导出为 `MODEL_BUDGET_MS`（仍在适配器 `REQUEST_TIMEOUT_MS = 5000` 之内）。

**判据与数字**（同一脚本）：

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 相关查询超时 | 4/12 | **0/12** |
| 模型作答率 | 58% | **75%**（mode=model 9 / index 3） |
| 剩余降级 | 超时 4 + 弃权 1 | 仅 `model_abstained` 3（模型判断，非故障） |
| 无关组零证据注入 | 0/32 | 0/32（未回退） |

**代价如实记录**：最坏延迟上升——无关组 P90 由 2728ms 升至 3762ms，那两次确实慢的请求（3877/3928ms）现在会等模型而非被提前切断。

**测试同步修正**：一条既有断言（"预算耗尽会中止被弃请求"）失败，原因是它写死等待 3200ms 去对 2500ms 预算——**行为一直正确，是常量动了**。修法不是改断言，而是**让它引用导出的常量**，并补一条保护断言 `MODEL_BUDGET_MS < 4000`，使预算涨过 fetch 上限时测试会大声失败而不是悄悄什么也没证明。

提交：`1aec4c7`。

## 三、"该弃权却开口"：否定式识别缺失

**现象**：盲测夹具（`test/retrieval-blind.test.ts`，18 用例）显示 7 个应弃权用例中只有 2 个正确弃权；"不要查询 Docker Compose，解释量子自旋"返回了 compose 条目。

**根因（两层）**：
1. **两份实现漂移**：否定/正向子句判定只有一份实现（`positiveRetrievalClauses`），索引与检索服务都调用它，**但本地匹配路径自己拿整串查询匹配**。
2. **共享词表漏词**：`negation` 词表有 不要/不需要/无需/不用/不想/排除/not/without/don't，**没有"不做"**。

**改动**：本地匹配改用同一函数（正向子句为空即弃权）；词表补 `不做|不查|不改|不写|不涉及|不考虑`。

**判据与数字**：

| 指标 | 初始 | 改用正向子句 | 扩词表后 |
|---|---|---|---|
| 精确率 | 0.333 | 0.364 | **0.381** |
| 误报数 | 16 | 14 | **13** |
| 正确弃权 | 2/7 | 3/7 | **4/7** |
| 召回率 | 0.727 | 0.727 | **0.727（不变）** |

**召回率不变是核心证据**：不是靠"少返回"换来的。两条例外用例的 `actual` 由 `[v1,v2]` 与 `[backup]` 变为 `[]`。

**真实库验证**：否定式查询选中 0 条；对照"召回预算怎么设置"命中 1 条，`matched: ["召回","预算"]`。

**未达标**：夹具自身验收字段仍是 `quality-gaps-present-not-product-acceptance`。剩余缺口是版本适用性（v1/v2 互串、不支持的 v3 应弃权却返回一切）与同义改写漏检 3 条。**改善数字不等于达到标准。**

提交：`0d5b2e4`。

## 四、回执说假话：`gaps` 把被排除的词报成覆盖缺口

**现象**：查询"不要查询召回预算，解释一下光合作用"，回执的 `gaps` 列出 **召回、预算**——而该字段的字面含义是"库里没有这个片段"。

**根因**：`gaps` 的基准取自**整串**查询。既有的 `noIntent` 只覆盖"整句皆否定"，覆盖不了"排除一个主题、同时问另一个主题"——而后者正是这句。另外基准还用了**未剥离填充词**的原始串，中文重叠二元组于是产生跨词边界碎片（"算怎""么设"）。

**改动**：`gaps` 的基准改为**正向子句**，且**先剥离填充词再切分**——与 `automaticRelevance` 的做法一致。`tokens` 与 `hasQuery` 保持不变。

**为什么只改 `gaps`**：首版把 `tokens` 一并改小，被既有测试挡住——它断言"否定式查询仍分出片段，只是没有检索意图"。**那条测试是对的**：`tokens`（提到过什么）与 `gaps`（没覆盖什么）是两个语义，我的改动超出了缺陷范围。

**判据与数字**（`node verification/r5/selection-why.mjs`，三侧验证）：

| 查询 | 修复前 gaps | 修复后 gaps |
|---|---|---|
| 不要查询召回预算，解释一下光合作用 | 含 召回、预算 等 12 个 | **解释、释一、一下、下光、光合、合作、作用** |
| 量子纠缠退相干与贝尔不等式 | — | 完整 12 个真实未命中片段（**未被静音**） |
| 召回预算怎么设置 | 回预、算怎、怎么、么设、设置 | **回预、设置**（命中词仍不进 gaps） |

**残余（未解决）**：`回预` 仍在。它是"召回预算"的词内 bigram，而命中条目里"召回""预算"是分开出现的，故"没有条目包含回预"技术上成立、对读者无意义。彻底解决需要真正的中文分词而不是重叠二元组。

提交：`c538702`（语义）、`9137281`（分词）。

## 六、未解决、留给后续的

- **本地自动匹配路径质量未达产品级**：盲测精确率 0.381、召回率 0.727、正确弃权 4/7，验收字段为 `quality-gaps-present-not-product-acceptance`。**本版不得被描述为"精准检索已达成"。**
- **版本适用性**：v1/v2 互串；不支持的版本（v3）应当弃权却返回一切。同义改写漏检 3 条。
- **两套匹配器的根本不一致**：索引的宽松证据链与 `automaticRelevance` 的严格匹配只在"正向子句"这一项上被对齐，其余未统一。
- **CJK 词内 bigram 伪缺口**：需真正的中文分词。
- **降级频率**：相关查询仍有约四分之一走降级（实测 4/12），降级路径质量低于模型路径。宿主重启与回填后需重新测量。
- **适配器侧三段拼接**（handoffContext + prepared.context + recallContext）自身仍无总预算。
- **宿主侧验收未闭环**：需重启宿主进程、执行 `reclassify --yes`、三项目视确认——**这三项只有人工能完成**，本文件不做替代性声明。
