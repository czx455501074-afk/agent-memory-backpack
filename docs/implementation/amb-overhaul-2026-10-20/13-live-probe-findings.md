## 2. 检索失败现场（Q6 的直接证据）

### 2.1 `amb_prepare`：有候选却零注入

查询：`AMB 插件 上下文预算 工具定义 200K 注入 检索噪声`

回执要点：
- `budget.usedChars: 0`，`retrieval.shown: 0`，`knowledge: []`
- `retrieval.considered: 318`（可见条目 318 条）
- `withheld: { count: 3, reason: "本地索引选出了候选，但它们没有通过字面证据复核，因此本次未注入" }`
- `retrieval.gaps: ["索噪"]`

**判定**：索引层选出了 3 条候选，被"字面证据复核"整批丢回。对中文改写查询，这条复核规则会把语义相近但字面不同的条目一律判死，表现为"库里有、但 agent 什么也拿不到"。

### 2.2 `amb_search_universal`：命中泛滥、排序失效

同一意图查询，`total: 119`，返回 8 条，其中**4 条与查询无关**：

| 排名 | 条目 | 与查询关系 |
|---|---|---|
| 1 | journal：子代理任务日记（本会话） | 弱相关 |
| 2 | memory：长内容分块读取 | 相关 |
| 3 | journal：上一轮整理日记 | 弱相关 |
| 4 | skill：**拉片审核**（短剧成片审核） | **无关** |
| 5 | skill：**视频生成参考形式** | **无关** |
| 6 | norm：接管仓库的最短路径 | 相关 |
| 7 | skill：**故事设定与剧情大纲** | **无关** |
| 8 | skill：**技能沉淀**（短剧/工程沉淀流程） | **无关** |

**噪声率 50%（4/8）**。噪声来源可归因：`why.matched` 显示它们只靠 `"预算"`、`"工具"`、`"定义"`、`"上下文"` 这类通用词命中，`coverage` 仅 0.5，但仍进入结果。短剧技能里出现"读取预算""工具归属"这类词，就足以被召回。

### 2.3 中文分词：跨词碎片污染判据

`queryTerms` 与 `matchedTerms` 出现 `"上下"`、`"下文"`、`"文预"`、`"具定"`、`"索噪"`、`"入噪"` 这类跨词 2-gram。后果：
- `matched` 统计虚高，看回执像"全命中了"；
- `missingTerms` 误报（`"索噪"`、`"入噪"` 这种并不存在的词被当成未命中项）；
- 排序无法区分"预算"出现在标题还是出现在无关段落。

**这是精度问题的主因之一，且是纯代码可修的。**

## 3. 自检口径与直觉相反（Q2 的旁证）

`amb_self_check` 输出：`knowledge-state: 知识版本 225，规范 0 条，流程 0 条`。

实际库内有 4 条 norm（宿主已加载的 AGENTS.md、Agent 工作入口、Project memory、Codex 全局工作规范），上下文段首也列出了这 4 条。原因在 `src/store.ts:2071-2072`：`hostProvided` 的规范被排除在"待注入规范"之外。

**判定**：这不是故障，但**口径不可解释**。用户看到"规范 0 条"会以为规范丢了。自检应报"规范 4 条（宿主已加载 4，需注入 0）"。

## 4. 写入侧噪声的实证（Q5 的写入侧）

一次只输出 `CHANNEL_OK` 的探测子代理，在库内留下 2 条 journal（`journal-task-13b184610beb0783`，知识版本 222→224），其中一条为空的收尾记录。

**判定**：噪声不只来自检索，也来自自动收尾。收尾归档对"零信息量会话"没有门槛，`support.status=missing` 只拦 `kind=memory`，日记不受此限。

## 5. 对设计的直接影响

1. `prepare` 的"字面证据复核"必须改为**分级**：字面命中优先，语义候选标注 `weak` 后仍可注入但限条数，而不是整批丢弃。
2. 中文检索需要词边界（词典/分词），至少把 2-gram 匹配从"命中即算"降为"辅助召回"，排序权重留在标题/关键词/别名上。
3. 覆盖回执里的 `matchedTerms`/`missingTerms` 必须只由真实词项构成，不能回传跨词碎片。
4. 自检统计口径要与用户直觉一致，并把"宿主已加载"单列。
5. 自动收尾要有"零信息量"门槛（无工具调用、无文件变更、无结论 → 不写长期 journal，只留事件）。
