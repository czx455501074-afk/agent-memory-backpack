# P2 阶段需求与验收标准

**状态**：待启动（P1 完成后）  
**目标**：用户界面、候选审阅、任务日记、跨端接续  
**预期交付**：2-4 周（取决于实测反馈）

## P2.1 本地管理界面

### 需求

实现基于 HTTP 的本地管理界面（不开发独立 Electron 应用），提供以下核心功能：

#### 功能 A：当前规范与偏好浏览

- 按范围（全局/项目）展示有效规范列表
- 显示规范 ID、版本、生效日期、内容摘要
- 搜索、过滤（按类型、范围、关键字）
- 查看规范历史版本（只读）
- 显示规范适用平台（DSH/Codex/全平台）

#### 功能 B：知识与工作流目录

- 展示所有活跃 workflow 与 norm
- 显示 workflow 的 isEntryPoint 标记
- 依赖关系可视化（子图或列表）
- 搜索完整流程（复用现有 FTS5 索引）
- 显示最后修改时间、当前版本号

#### 功能 C：候选审阅

- 列出所有待审阅提案（pending 状态）
- 显示提案 ID、来源 principal、基础版本、发现时间、到期时间
- 展开提案内容与证据
- 所属流程、关联任务、发现者信息
- 批量操作：批准、拒收、归档、标记为需补证

#### 功能 D：任务与日记

- 列出最近任务（按完成时间或状态）
- 显示任务 ID、所属项目、开始/结束时间、状态（进行中/完成/暂停/失败）
- 任务日记摘要（自动生成或用户手动编辑）
- 关联的经验修改、提案、规范版本
- 导出任务记录为可读 Markdown

#### 功能 E：临时资料管理

- 显示所有 collected 临时资料（URL、标题、摘要）
- 显示保存时间、到期时间、关联任务
- 到期提醒与清理状态
- 手动续期或删除
- 统计总量、占用大小

#### 功能 F：平台能力与故障

- 显示 DSH 与 Codex 的连接状态
- 显示已验证能力（Managed/ReadOnlySnapshot/Ungoverned）
- 版本号、最后同步时间
- 故障日志与重试状态
- 手动重连按钮

### 技术方案

- **框架**：Express（已有依赖）
- **前端**：Vanilla JS + HTML5 或轻量级框架（Vue/React）
- **数据源**：直接查询 SQLite Store + 适配器状态
- **认证**：本机回环仅 + 简单 session（不复杂的 OAuth）
- **响应体**：JSON API + Server-Rendered HTML

### 验收标准

- [ ] 界面在 localhost:47632（或可配置）可访问
- [ ] 规范浏览功能：无错误列表 5+ 条规范
- [ ] 候选审阅：显示所有 pending 提案，支持批准/拒收
- [ ] 任务浏览：显示 3+ 已完成任务及其日记
- [ ] 临时资料：显示到期日期，手动续期生效
- [ ] 故障恢复：DSH 离线时显示 Ungoverned，重连后恢复
- [ ] 安全性：不允许跨域请求，凭据不在 HTML 中暴露

## P2.2 候选提案审阅与批准流程

### 需求

实现从提案提交→分类→评审→生效的完整流程。

#### 阶段 1：提案分类与初检

**输入**：新提案（来自 `amb_submit_experience` 或事件采集）

**程序检查**：
- 幂等性验证（重复提交拒绝）
- 来源与范围验证（principal 与 projectId 匹配）
- 字段完整性（discovery, workflowId, baseRevision）
- version 冲突检测（baseRevision 与当前版本）

**结果**：提案进入 pending 状态或立即拒收

#### 阶段 2：模型分类与建议

**触发**：通过初检的提案

**由模型完成**（使用 summon_expert）：
- 确定内容类型（规范/偏好/事实/经验/日记）
- 确定适用范围（全局/项目/平台）
- 检测与已有条目的重复/冲突
- 评估复用价值与证据质量
- 推荐操作（直接批准/需补证/拒收）
- 生成摘要与分类标签

**程序作用**：保存分类结果，不代表已自动生效

#### 阶段 3：用户审阅与决策

**界面**：候选审阅面板

**用户操作**：
- 查看提案完整内容 + 分类建议
- 批准：提案生效，保存新版本，记录批准人与时间
- 拒收：记录拒收理由，标记为 rejected
- 补证：转入"待补证"列表，标记期限（默认 30 天）
- 合并：与已有条目合并，需指定目标版本

**程序保证**：原子事务，所有修改同时生效或全部回滚

#### 阶段 4：生效与索引更新

**批准时**：
- 在 revisions 表插入新版本
- 更新 knowledge.head_revision（CAS 检查）
- 重新构建 FTS5 全文索引
- 通知所有适配器新知识版本
- 记录变更事件

**拒收时**：
- 提案状态标记为 rejected
- 保存拒收理由与时间
- 通知提交者

### 超时与生命周期

- **待补证**：默认 30 天，到期自动归档（可选手动续期）
- **重要冲突**：保留在集中待裁决列表，需明确处理
- **已拒收**：保留历史 90 天供查阅

### 验收标准

- [ ] 提案通过初检后进入 pending 状态
- [ ] 模型分类完成，生成可读的分类建议
- [ ] 用户批准提案后，新版本立即在搜索中可用
- [ ] 拒收提案标记为 rejected，理由可查询
- [ ] 待补证提案 30 天后自动归档（不生效）
- [ ] 冲突提案保留在列表中等待明确决策
- [ ] 所有操作可追溯（变更历史、审批记录）

## P2.3 任务日记、跨端接续与导出

### 需求

#### 功能 A：任务生命周期管理

**任务数据结构**：
```json
{
  "id": "task-xxx",
  "projectId": "project-demo",
  "title": "用户输入的任务标题或自动从首条消息提取",
  "status": "in_progress|completed|paused|failed",
  "startedAt": "2026-10-10T12:00:00Z",
  "completedAt": "2026-10-10T13:30:00Z",
  "summary": "自动生成或用户编辑的简短描述",
  "notes": "用户手动补充的观察",
  "relatedExperiences": ["exp-id-1", "exp-id-2"],
  "relatedProposals": ["proposal-id-1"],
  "knowledgeVersion": 42,
  "unfinishedItems": ["未解决项 1", "未解决项 2"]
}
```

**自动记录**：
- 任务开始时：sessionId → taskId，记录触发信息
- 任务进行中：代理提交的 events（turn_started, tool_used, turn_stopped）
- 任务完成：生成日记，记录知识版本、重要修改、提案等
- 任务切换：保存当前状态，标记为 paused

**用户操作**：
- 编辑任务标题、摘要、笔记
- 手动标记完成/失败/暂停
- 关联相关规范或提案

#### 功能 B：跨端接续

**接续流程**：

1. **离开一端**（DSH 或 Codex）：
   - 自动提交 turn_stopped 事件
   - 保存任务当前状态到 Store
   - 生成交接摘要

2. **在另一端恢复**：
   - 用户选择"继续已有任务"
   - 系统显示可用任务列表
   - 用户选择后，系统获取并展示：
     - 任务摘要与最后状态
     - 当前有效规范（完整版本）
     - 相关经验与工作流入口
     - 文件与环境检查结果
   - 接收端验证文件权限、仓库分支等
   - 注入接续上下文

3. **上下文注入**：
   ```
   [Task Handoff]
   Task: task-xxx "用户的任务"
   Status: 完成度 70%，暂停待继续
   Last: DSH, 2026-10-10 12:30
   Knowledge: version 42
   Related Workflows: workflow-1, workflow-2
   Important: 未解决项列表
   Files: 工作目录同步检查结果
   ```

#### 功能 C：导出与记录

**导出格式**：Markdown + JSON

**Markdown 导出**：
```markdown
# 任务记录：用户的任务

**任务 ID**：task-xxx  
**项目**：project-demo  
**时间**：2026-10-10 12:00 ~ 13:30  
**状态**：完成

## 摘要
自动或手动生成的任务描述。

## 进展
- 12:00 任务开始
- 12:15 执行了流程 X
- 13:00 遇到问题 Y，已解决
- 13:30 任务完成

## 关联知识
- 规范 v42：当前项目规范
- 流程：workflow-1（执行过）
- 经验：exp-id-1（已提交）
- 提案：proposal-id-1（待审阅）

## 未解决项
- [ ] 功能 Z 需进一步验证

## 备注
用户的手动笔记。
```

**JSON 导出**：完整结构化数据（用于备份或迁移）

**保留策略**：
- 日记正文：永久保留（已完成任务）
- 事件详情：30 天自动清理
- 临时资料引用：按资料本身的到期时间清理
- 源提案与规范：遵循各自的版本控制

### 验收标准

- [ ] 任务开始时自动记录 ID、时间、触发信息
- [ ] 任务完成时自动生成日记（500 字以内）
- [ ] 跨端接续时显示完整上下文（摘要、规范、工作流）
- [ ] 文件环境检查无误提示
- [ ] 导出 Markdown 可读，包含关键信息
- [ ] 导出 JSON 完整，包含所有元数据
- [ ] 日记与临时资料采用不同的清理策略（日记永久，资料 90 天）
