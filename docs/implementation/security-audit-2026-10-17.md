# 安全性审计（2026-10-17）

按发行目标要求的四个维度之一做安全审计。**方法：先读实现，再实测**——因为"代码里有防护"和"防护真的生效"是两件事。

## 一、本地 HTTP 服务的攻击面（实测）

这个核心监听本地端口，用户机器上任何程序、任何打开的网页都可能尝试访问它。逐条实测：

| 攻击面 | 实测结果 |
|---|---|
| 监听地址 | `127.0.0.1:47631` —— **仅回环，局域网不可达** |
| 不带任何凭据 | **401** `unauthorized` |
| 有令牌但缺协议头 | **426** `protocol_mismatch` |
| 有协议头但无令牌 | **401** `unauthorized` |
| 令牌错误（64 个 f） | **401** `unauthorized` |
| 合法请求但恶意 `Origin` | **403** `origin_denied` |
| 合法请求但 `Host: evil.example` | **403** `host_denied` |
| `Host: 127.0.0.1:9999`（端口不符） | **403** `host_denied` |
| `Host: attacker.com:47631` | **403** `host_denied` |
| 完全合法的请求 | **200** |

**第一轮的假象值得单独记**：用 `fetch` 发恶意 `Host` 时返回了 200，看上去像是校验失效。**但 `fetch` 不允许设置 `Host`**（它是禁止头），实际发出的仍是真实 Host——**那次测试什么都没证明**。改用 `node:http` 的底层 `request()` 后才测到真实行为（403）。**结论：一次"通过"如果方法本身够不到目标，它既不能证明通过，也不能证明失败。**

## 三、凭据处理

- 初始化时逐条收紧 ACL（"凭据 ACL 已收紧为仅当前用户（+SYSTEM/Administrators），继承已移除"）。
- 所有输出**只打印路径不打印值**（自检里那一项原文是 `64 characters; value not printed`）。
- 导出侧有守卫：识别"密钥形状"的内容会拒绝导出（**已知边界**：历史修订里若有此类字符串会挡住整次导出，已在发行判定第九节单列）。
- 面板侧凭据不落到浏览器：管理操作经宿主转发，页面拿不到 admin 凭据。

## 四、失败时的行为

- 鉴权失败一律**明确拒绝并给出原因码**（`unauthorized` / `protocol_mismatch` / `origin_denied` / `host_denied` / `scope_denied`），**不降级放行**。
- 跨项目访问返回 `scope_denied`；写全局条目需要显式 admin 决定（`Only an explicit admin decision may write a global entry`）。

## 五、未覆盖与不确定性（如实标注）

- **没有做**渗透式的持续模糊测试；本审计是**一次性的定向检查**，不构成"不存在其他漏洞"的证明。
- **没有审**依赖项的已知漏洞（未跑依赖扫描）。
- **没有审** Tauri 桌面外壳的 Rust 侧（本轮只看了核心服务与 CLI 的数据面）。
- 上文"无用户输入进入 SQL 文本"是基于**通读 21 处模板语句**得出的，**样本是全部而非抽样**，但仍依赖阅读的准确性而非工具验证。
