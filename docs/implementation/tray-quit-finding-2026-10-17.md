# 托盘退出行为核查（2026-10-17）

## 背景

早前有一项反馈：「右键托盘图标点击退出已经失效」。当时判断"很可能不是本插件的问题"，但**没有做控制实验**，所以一直挂在遗留项里。本轮改为读代码取证，把这一项关闭。

## 证据

### 本插件（Tauri 桌面版）的退出路径：干净

`desktop-tauri/src-tauri/src/` 下两处触发退出的地方都直接退出，**没有任何拦截**：

- 托盘菜单「彻底退出」（`tray.rs`）：菜单项 id 为 `quit`，处理分支直接 `app.exit(0)`。
- 前端请求退出（`commands.rs`）：`"quit" => { log::info!("退出应用（前端请求）"); app.exit(0); }`。

全仓搜索 `prevent` / `CloseRequested` / `on_window_event` / `RunEvent::ExitRequested`，只有一处 `prevent`：

- `lib.rs`：`WindowEvent::CloseRequested { api, .. } => { ... api.prevent_close(); }` —— 这是**关闭窗口时隐藏到托盘**（close-to-tray），是该应用**有意声明**的行为，与"退出"是两条不同的路径。代码注释也写明"Hiding is not quitting: the process stays alive in the tray"。

**结论**：本插件的托盘退出是一条直路，不存在"点了没反应"的实现空间。

### 宿主（DSH）的退出路径：拦截后确认

DSH 的 `app.asar` 内 `before-quit` 处理是**无条件** `event.preventDefault()`，然后弹一个确认对话框，只有用户确认后才走 `finishQuit()`。也就是说，它的"退出"是**两段式**：先确认，再退出。

当确认对话框没有被看到（不在前台、被其他窗口盖住、或用户以为已关闭）时，表现就是**"点了退出但没退出"**。

## 结论

| 行为 | 本插件（Tauri） | 宿主（DSH） |
|---|---|---|
| 托盘「彻底退出」 | `app.exit(0)`，直接退出 | `before-quit` 拦截 → 弹确认 → 确认后才退出 |
| 关闭窗口 | `prevent_close()` → 隐藏到托盘（有意设计） | —— |

**收到的反馈描述的现象，与本插件的实现不符、与宿主的实现相符**：宿主确实是"确认后退出"，而确认对话框是否被看到决定了它表现为"退出成功"还是"点了没用"。

因此本项**关闭**，归类为宿主行为，不再作为本插件的遗留项。若日后仍遇到，排查顺序是：确认对话框是否出现过（在前台/被遮挡/在另一屏），而不是怀疑插件的托盘实现。

## 本次未做

- 没有做"移除插件后重测"的对照实验：要移除插件需改动宿主配置并重启宿主，会中断正在工作的会话，成本高于收益；而上述代码证据已足以定位责任方（两边实现都读到了）。
- 没有验证 DSH 的确认对话框在用户环境中的具体表现（需要用户侧观察）。
