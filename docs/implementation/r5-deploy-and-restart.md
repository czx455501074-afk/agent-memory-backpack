# R5 部署与重启手册（真实用户体验验收的前置）

代码改完不等于用户能用上。**宿主加载的是部署目录的副本，不是源码目录**——这一步跳过，就会出现"改完重启却毫无变化"。本手册给出可照抄的步骤、判据与回滚方式。

## 一、先看清三层（这是所有踩坑的根源）

| 层 | 位置 | 生效条件 |
|---|---|---|
| 源码 | 仓库目录 `<REPO>` | 只影响测试与打包输入 |
| 产物 | `npm run pack:local` 生成的目录（见 `artifacts/latest.json`） | 打包时生成的副本 |
| **部署** | 宿主 profile 的 `node_modules` 链接指向的**部署目录**（本机为 `<DEPLOY_DIR>`，由 `scripts/deploy-plugin.mjs` 维护） | **只有这一步做完，宿主才可能加载新代码** |

实测（2026-10-17）：四个 profile（`amb-verify` / `desktop` / `headless` / `web`）都 `link:` 到同一个部署目录；部署目录的 `index.mjs` 时间戳为 13:36，而源码 `dist/src` 已到 14:20 → **部署落后于源码**，此时重启宿主只会加载旧代码。

## 二、标准步骤（按顺序，缺一步都不算完成）

```powershell
# 0. 先确认基线是绿的：失败项不许带进部署
npm run build
npm test                     # 期望：0 失败；跳过项必须带原因

# 1. 打包（含全量语法门，见 scripts/package.mjs）
npm run pack:local

# 2. 部署到各 profile（脚本会读穿链接复核，失败即报失败）
npm run deploy:plugin

# 3. 重启宿主（DSH 与 Codex 各一次）
#    —— 这一步必须由人来做：重启宿主会中断当前会话，agent 不能自我重启
```

## 三、重启后 60 秒验收（每条都要留原始输出）

```powershell
# 3.1 自检：配置 / 库完整性 / 核心可达 / 协议版本
amb doctor

# 3.2 版本与部署一致性：确认宿主加载的是哪一份
amb --version

# 3.3 检索：库里存在的一条规范，用它的准原文查询能否命中
#     期望：命中该规范，且它是首条（基线见 r5-retrieval-baseline.md）
amb search --query "<一条规范里的原话>"

# 3.4 注入回执：同一次准备调用里，命中的词不再被报成缺口
#     期望：matchedTokens 非空；gaps 不包含被命中规范提供的词

# 3.5 待审队列：规模是否回到"人能审完"的量级
amb proposals --state pending
```

3.3–3.5 的量化口径与对照值见 [`r5-retrieval-baseline.md`](r5-retrieval-baseline.md)。

## 四、回滚

- 部署脚本每次部署前后都留有可追溯记录；要回到上一版，重新用上一版的产物执行第 2 步即可。
- 数据侧不做回滚实验：**真实库是用户的权威副本**，任何验证都在库副本（`VACUUM INTO` 或临时 `--data-dir`）上进行。
- 卸载只删数据目录、不动源文件与宿主配置（见 `README.md` 的卸载节）。

## 五、这一版的两条纪律

1. **没有重启宿主的验收不算通过**：进程里跑的是旧插件集合，配置与磁盘一致也不能证明用户看得到新行为。
2. **不把"首次采纳"改成自动**：安装后的首次扫描是唯一的闸门，顺滑体验不能以放开它为代价（同类项目的失败模式：候选堆积）。
