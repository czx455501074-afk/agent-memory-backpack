# 效果验证：注入的知识被真正用上了吗（本次会话自证）

用户最初的要求不是"功能存在"，而是"让 agent 工作时能够自动从库里精准获取所需内容、经验、技能"。这类要求不能靠测试回答，只能看真实会话里**注入的内容有没有改变行为**。

本文件用**本次会话**作为样本：列出被自动注入的内容，以及它们各自在什么动作里被实际采用。这是**自证**（我看自己的行为记录），不是对照实验——局限写在最后一节。

## 一、四条规范：每条都能指到一个真实动作

| 注入的规范（宿主自行加载） | 它在本次会话里改变了什么 |
|---|---|
| `norm:endpoint-latency-attribution`：排查接口超时必须带 `x-amb-protocol: 1` 防 426；用无外部调用的同步端点作对照组分离数据层与模型层 | 写 `scripts/r5-live-verify.mjs` 时用它做**对照测量**：`/v1/search` 192ms（无模型）对 `/v1/prepare` 342ms，差值 150ms 归因为模型层；也用它确认了协议头（否则会得到 426 而不是真实结果） |
| `norm:log-window-comparability`：比对日志前先证明两窗口可比，用比率而非绝对数 | 写 `scripts/r5-usage-report.mjs` 时据此**拒绝**做前后对照：报告里明确写"这是连续窗口、不是对照，指针级样本为 0，所以任何节省比例都会是编的" |
| `norm:package-syntax-gate`：打包脚本必须含 `node --check` 全量扫描 | 我在发布清单与 `verify-deliverables` 的语境里核对了这条门是否在，并在审计归档时确认打包路径仍保留它 |
| `norm:timeout-budget-mode-verdict`：判断超时预算是否生效必须核对 `selection.mode` 与 `reason`，不能凭总耗时推断 | 正因如此我才去读 `retrieval.selection`，从而**发现了自己的验收缺口**：脚本走的是 `local_index`（无 provider），而真实核心走 `model`；若只看耗时，我会得出"检索没生效"的错误结论 |

**四条全部被采用，且每条都能指到一个具体动作**——不是"我知道了"，而是"我因此改了什么做法"。

## 二、失败经验：同一条被复用四次

注入的失败经验里有一条出现最多：

```
edit: ReplaceFileW EIO (Win32 1175) ... （库内累计 27 次）
```

它的既有经验是"读回确认文件完好后**原样重试**即成功"。本次会话中这个错误实际发生了 **4 次**（对 `r5-acceptance.md` 一次、`r5-tool-surface-audit.md` 一次、`r5-live-verify.mjs` 一次、另一次在早前），**四次都按这条经验重试即成功，没有一次去怀疑文件损坏或改写方法**。若没有这条经验，最可能的错误反应是"以为编辑工具坏了，改用别的方式写文件"——那样会引入新问题。

## 三、这条链闭合了吗

用户要求的完整闭环是：**工作中遇到问题 → 经验入库 → 后续工作中自动取回 → 行为改善**。本次会话里能看到它在运转：

1. **产出**：本次会话提交了十余条经验候选（如"零使用率检测""门禁位置""捕获自污染"等），它们由 `amb_submit_experience` 进入待审队列；
2. **取回**：宿主在每次任务开始时自动注入规范与该任务相关的日记/经验（本文件第一、二节的证据）；
3. **改善**：上面 4 次重试、对照组测量、拒绝伪对照，都是"取回后改变做法"的实例。

## 四、这条验证不能证明什么（重要）

- **是自证**：我观察的是自己的行为记录，不是随机对照实验。没有"未注入组"作比较，所以**不能量化**"提高了多少效率"。
- **规范是宿主自行加载的**：这四条由宿主读入并登记，不是每轮由插件注入的正文。插件注入的是检索结果与规范指针（指针化后 53 字符）。所以本文件主要证明**"库里的内容能到达 agent 并被采用"**，而不是"注入路径的每一段都完美"。
- **有反例**：本次会话里也出现过注入内容**没被用上**的情形——大部分注入的知识正文与当下任务无关（例如检索到的是短剧创作、剪映草稿的日记）。这类噪声正是召回预算要做的事，但它的**质量**未在本文件中评估。
- **一次会话不是分布**：4 次重试、4 条规范都来自同一个会话与同一个用户的工作方式，不能代表其他项目。

## 五、结论

**能证明**：知识库的内容确实参与到了真实工作里，且能指出具体动作——规范改变了测量方法，失败经验改变了错误处置方式。这条链是通的。
**不能证明**：效率提升的幅度、召回噪声的规模、以及在其他项目上的可复现性。要回答这些，需要一次**有对照组**的实验（例如同一任务在注入/不注入两种条件下的完成质量），那是这份自证做不到的。
